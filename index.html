// uvm_test
Test Class
Top-level test class that extends uvm_test. Instantiates the environment and starts sequences. Each test scenario is a new test class.
uvm_testbuild_phase
The test class is the entry point. It creates the env, optionally sets factory overrides, and starts sequences in run_phase.
test class skeleton
class test extends uvm_test;
  `uvm_component_utils(test)
  
  env envh;
  
  function new(string name, uvm_component parent);
    super.new(name, parent);
  endfunction
  
  function void build_phase(uvm_phase phase);
    super.build_phase(phase);
    envh = env::type_id::create("envh", this);
  endfunction
  
  task run_phase(uvm_phase phase);
    phase.raise_objection(this);
    // start sequences here
    phase.drop_objection(this);
  endtask
endclass

// CONCEPT 02
UVM Phases
// Ordered execution phases control build, connect, and simulation lifecycle

Build/Connect Phases (Functions)

build_phase
Create and configure child components. Called top-down: parent before child.
// type: function | order: top-down
connect_phase
Connect TLM ports between components. Called bottom-up.
// type: function | order: bottom-up
end_of_elaboration_phase
Final topology adjustments. Print topology here.
// type: function | order: bottom-up
start_of_simulation_phase
Display banner, reset signals, initialize variables.
// type: function | order: bottom-up

Run Phase (Task — Time-Consuming)

run_phase
Main simulation phase. Must raise/drop objections to control simulation end. Runs in parallel across all components.
// type: task | fork-join | objection-controlled
extract_phase
Extract and process data from DUT/monitors.
// type: function | post-run
check_phase
Check for errors. Scoreboard final comparison.
// type: function | post-run
report_phase
Print simulation results and coverage summary.
// type: function | final
final_phase
Close files, databases. Last phase before simulation exits.
// type: function | absolute final
phases example — objections & banner
class test extends uvm_test;
  function void start_of_simulation_phase(uvm_phase phase);
    super.start_of_simulation_phase(phase);
    `uvm_info("BANNER", "=============================================", UVM_NONE)
    `uvm_info("BANNER", " Starting Simulation: my_test ", UVM_NONE)
    `uvm_info("BANNER", "=============================================", UVM_NONE)
  endfunction
  
  task run_phase(uvm_phase phase);
    phase.raise_objection(this);    // Simulation won't end
    `uvm_info(get_type_name, "Running test...", UVM_LOW)
    #100;
    phase.drop_objection(this);    // Allow simulation to end
  endtask
  
  function void end_of_elaboration_phase(uvm_phase phase);
    super.end_of_elaboration_phase(phase);
    uvm_top.print_topology();   // Print component hierarchy
  endfunction
endclass
// CONCEPT 03
Factory Override
// Replace component types at runtime without changing testbench code
🏭
// uvm_factory
Type Override — Replace a class with a subclass globally
Factory overrides let you swap driver1 or driver2 at the test level using preprocessor defines, without modifying any other code. This is the power of UVM's factory pattern.
set_type_override_by_typetype_id::createuvm_factory
Key insight: All components must be created with type_id::create() instead of new(). This registers them with the factory, enabling overrides. The override must be set BEFORE the component is created.

Use `ifdef DRV1 compile-time flags or test-level overrides to switch implementations.
factory override — base + child drivers
// Base driver — default implementation
class base_driver extends uvm_driver;
  `uvm_component_utils(base_driver)
  function new(string name = "base_driver", uvm_component parent);
    super.new(name, parent);
  endfunction
endclass

// Override 1: driver1
class driver1 extends base_driver;
  `uvm_component_utils(driver1)
  function new(string name = "driver1", uvm_component parent);
    super.new(name, parent);
  endfunction
endclass

// Override 2: driver2
class driver2 extends base_driver;
  `uvm_component_utils(driver2)
  function new(string name = "driver2", uvm_component parent);
    super.new(name, parent);
  endfunction
endclass
test class — applying override
class test extends uvm_test;
  function void build_phase(uvm_phase phase);
    uvm_factory factory = uvm_factory::get();
    envh = env::type_id::create("envh", this);
    super.build_phase(phase);

    `ifdef DRV1
      set_type_override_by_type(
        base_driver::get_type(),
        driver1::get_type()
      );
    `elsif DRV2
      set_type_override_by_type(
        base_driver::get_type(),
        driver2::get_type()
      );
    `endif
    
    factory.print();  // Show current factory state
  endfunction
endclass

// Compile with: +define+DRV1 or +define+DRV2
Important: Note that super.build_phase(phase) is called AFTER creating the env. The override must be set before child component creation. When base_agent calls base_driver::type_id::create(), the factory will instead create driver1 or driver2.
// CONCEPT 04
Sequences & Sequencers
// The sequence-sequencer-driver trio — how stimulus is generated and driven

🔄 Sequence Flow

1
sequence.start(sequencer)
↓ arbitration
2
wait_for_grant()
↓ granted
3
req.randomize() → send_request(req)
↓ to driver
4
driver: seq_item_port.get_next_item(req)
↓ drive DUT
5
seq_item_port.item_done() → wait_for_item_done()
complete seq + seqr + driver example
class seq_item extends uvm_sequence_item;
  rand int data;
  `uvm_object_utils(seq_item)
  function new(string name = "seq_item");
    super.new(name);
  endfunction
endclass

class sequence_ex extends uvm_sequence#(seq_item);
  `uvm_object_utils(sequence_ex)
  seq_item req;
  
  task body();
    req = seq_item::type_id::create("req");
    wait_for_grant();
    assert(req.randomize());
    send_request(req);
    wait_for_item_done();
  endtask
endclass

class driver extends uvm_driver#(seq_item);
  `uvm_component_utils(driver)
  
  task run_phase(uvm_phase phase);
    forever begin
      seq_item_port.get_next_item(req);
      #50;  // Drive the DUT
      seq_item_port.item_done();
    end
  endtask
endclass

seqh.start(envh.agnth.seqrh);

UVM Config DB
// Pass configuration objects between components without direct references

CONFIG DB API

MethodDescription
uvm_config_db#(T)::set()Store a value — 4 args: context, path, field, value
uvm_config_db#(T)::get()Retrieve a value — 4 args: context, path, field, variable

PATH WILDCARDS

"envh.*" — all children of envh
"envh.cb" — specific component
"*" — all components in hierarchy
"" — current component only
config db set & get example
// TEST: Set control value for all children of envh
class test extends uvm_test;
  int ctrl = 1;
  
  function void build_phase(uvm_phase phase);
    super.build_phase(phase);
    envh = env::type_id::create("envh", this);
    
    // Set: context=this, path="envh.*", field="control"
    uvm_config_db#(int)::set(this, "envh.*", "control", ctrl);
  endfunction
endclass

// CLASS_B: Get the control value
class class_b extends uvm_component;
  int ctrl;
  class_c cc;
  
  function void build_phase(uvm_phase phase);
    super.build_phase(phase);
    
    // Get: fatal if not found
    if(!uvm_config_db#(int)::get(this, "", "control", ctrl))
      `uvm_fatal(get_type_name(), "get function failed")
    
    // Conditionally create component based on config
    if(ctrl)
      cc = class_c::type_id::create("cc", this);
  endfunction
endclass
// CONCEPT 07
TLM Ports
// Transaction Level Modeling — blocking, non-blocking, and implementation ports
Port TypeDirectionBlockingUse Case
uvm_put_portProducer → ConsumerYes (put/try_put/can_put)Send transactions to consumer
uvm_get_portConsumer ← ProducerYes (get/try_get/can_get)Pull transactions from producer
uvm_blocking_put_portProducer → ConsumerBlocking onlySimple one-way flow
uvm_blocking_get_portConsumer ← ProducerBlocking onlySimple pull model
uvm_put_impImplementationBothConsumer implementation (has put/try_put/can_put)
uvm_analysis_port1-to-manyNon-blocking writeBroadcast to monitors/scoreboards
blocking + non-blocking TLM port example
class producer extends uvm_component;
  uvm_put_port#(int) tlm_put;  // Supports blocking + non-blocking
  
  task run_phase(uvm_phase phase);
    int data = 20;
    tlm_put.put(data);       // blocking put
    tlm_put.try_put(data);   // non-blocking put (returns bit)
    tlm_put.can_put();       // check if can put
  endtask
endclass

class consumer extends uvm_component;
  uvm_put_imp#(int, consumer) tlm_imp;  // Implementation port
  
  task put(int val);         // implements blocking put
    #10;
    `uvm_info(get_type_name(), $sformatf("got: %0h", val), UVM_LOW)
  endtask
  
  function bit try_put(int val);  // non-blocking
    `uvm_info(get_type_name(), $sformatf("try_put: %0d", val), UVM_LOW)
    return 1;
  endfunction
  
  function bit can_put();
    return 1;
  endfunction
endclass

// In env connect_phase:
prh.tlm_put.connect(crh.tlm_imp);
// CONCEPT 08
Analysis Ports
// Broadcast transactions to multiple subscribers — 1-to-N write() communication

ANALYSIS PORT FLOW

producer — uvm_analysis_port
↓ .write(t_h) broadcasts to all connected
consumer_a — uvm_analysis_imp
consumer_b — uvm_analysis_imp
consumer_c — uvm_analysis_imp
// Each consumer implements write()
producer with analysis port
class producer extends uvm_component;
  uvm_analysis_port#(transaction) producer_put;
  
  function new(string name, uvm_component parent);
    super.new(name, parent);
    producer_put = new("producer_put", this);
  endfunction
  
  task run_phase(uvm_phase phase);
    transaction t_h = transaction::type_id::create("t_h", this);
    assert(t_h.randomize());
    producer_put.write(t_h);  // broadcast!
  endtask
endclass
consumers with analysis imp
class consumer_a extends uvm_component;
  uvm_analysis_imp#(transaction, consumer_a) consumer_imp;
  
  function void write(transaction t_h);
    `uvm_info(get_type_name(),
      $sformatf("received: %0d", t_h.data), UVM_LOW)
  endfunction
endclass

// Consumer B and C are identical pattern...

// In env connect_phase — connect 1 port to 3 imps:
p_h.producer_put.connect(ca_h.consumer_imp);
p_h.producer_put.connect(cb_h.b_imp);
p_h.producer_put.connect(cc_h.c_imp);
// All 3 consumers get write() called automatically
Key Rules:
• analysis_port — no blocking; write() returns immediately
• One port connects to unlimited subscribers
• write() is void function — no return value
• Used in monitors to broadcast to scoreboard/coverage
// CONCEPT 09
TLM FIFOs
// Buffer between producer and consumer — decouples generation from driving
tlm_fifo connecting generator to driver
class generator extends uvm_component;
  uvm_blocking_put_port#(packet) put_port;
  
  task run_phase(uvm_phase phase);
    packet pkt = packet::type_id::create("pkt", this);
    pkt.randomize();
    put_port.put(pkt);  // put to FIFO
  endtask
endclass

class driver extends uvm_driver;
  uvm_blocking_get_port#(packet) get_port;
  packet pkt;
  
  task run_phase(uvm_phase phase);
    get_port.get(pkt);  // get from FIFO
    pkt.display("driver");
  endtask
endclass

class agent extends uvm_agent;
  generator genh;
  driver drvh;
  uvm_tlm_fifo#(packet) fifoh;  // The FIFO!
  
  function new(string name, uvm_component parent);
    super.new(name, parent);
    fifoh = new("fifoh", this);  // created in new()
  endfunction
  
  function void connect_phase(uvm_phase phase);
    genh.put_port.connect(fifoh.put_export);
    drvh.get_port.connect(fifoh.get_export);
  endfunction
endclass

FIFO EXPORTS

ExportUsed By
put_exportProducer puts items in
get_exportConsumer gets items out
peek_exportPeek without removing
get_peek_exportCombined get+peek
When to use uvm_tlm_fifo:
• Generator runs at its own rate
• Driver runs at its own rate
• FIFO buffers the difference
• Useful when gen faster/slower than driver
• Default size = 1 (acts as synchronizer)
• new("fifoh", this) — created in new() not build_phase
// CONCEPT 10
Field Macros
// Auto-generate copy, compare, print, pack, unpack for sequence_item fields
field macros + copy/clone example
class packet extends uvm_object;
  int data;
  reg [3:0] addr;
  logic enable;
  
  // Wrap all fields between begin/end
  `uvm_object_utils_begin(packet)
    `uvm_field_int(data,   UVM_ALL_ON)    // all ops
    `uvm_field_int(addr,   UVM_NOCOPY)    // skip copy
    `uvm_field_int(enable, UVM_NOCOMPARE) // skip compare
  `uvm_object_utils_end
endclass

// copy() uses do_copy — automatic with field macros
packet p1_h = packet::type_id::create("p1_h");
packet p2_h = packet::type_id::create("p2_h");
p2_h.copy(p1_h);   // deep copy p1 → p2

// clone() = copy + new allocation
$cast(p2_h, p1_h.clone());

// compare() using do_compare
if(p2_h.compare(p1_h))
  $display("comparison success");

FIELD MACRO FLAGS

FlagEffect
UVM_ALL_ONEnable all operations
UVM_NOCOPYSkip field in copy()
UVM_NOCOMPARESkip in compare()
UVM_NOPRINTSkip in print()
UVM_NOPACKSkip in pack()
custom do_copy override
virtual function void do_copy(uvm_object rhs);
  transaction t_h = new();
  $cast(t_h, rhs);
  this.addr = t_h.addr;
  this.data = t_h.data;
endfunction

// CONCEPT 12
UVM Objections
// Objection mechanism controls when run_phase ends — simulation won't end until all objections are dropped

OBJECTION RULES

• At least ONE component must raise an objection
• Simulation ends when ALL objections are dropped
• Raise BEFORE the work, drop AFTER
• Never drop an objection you didn't raise
• Multiple components can raise concurrently
• Forgetting to drop = simulation hangs!
driver + monitor concurrent objections
// driver: raises, does work, drops
task run_phase(uvm_phase phase);
  phase.raise_objection(this);
  `uvm_info("RUN PHASE","objection raised",UVM_LOW)
  #10;
  phase.drop_objection(this);
endtask

// monitor: FORGOT to drop — simulation hangs!
task run_phase(uvm_phase phase);
  phase.raise_objection(this);
  #50;
  // phase.drop_objection(this); <-- BUG!
endtask
best practice — objections in test only
// RECOMMENDED: Only test class manages objections
class test extends uvm_test;
  task run_phase(uvm_phase phase);
    super.run_phase(phase);
    phase.raise_objection(this);
    
    // Run all sequences
    vseq.start(envh.v_seqr);
    
    phase.drop_objection(this);
  endtask
endclass

// Set drain time (wait after all dropped)
phase.phase_done.set_drain_time(this, 100);

// Check objection count:
int count = phase.get_objection_count(this);
Debug tip: If simulation hangs, add
+UVM_OBJECTION_TRACE to the command line to see all raise/drop events with component names and counts.
